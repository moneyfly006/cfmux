控制面 · cfmux.pages.dev（你打开的后台）

/admin 后台仪表盘 · 密码登录
改设置 / 管数据面 / 导入优选 / 改内核配置
/sub 生成订阅
读 KV → 过滤 → 排序 → 输出 7 种格式
/panel 公开状态页 · /api/stats 漏斗
/api/kernel 代理读写数据面内核配置
它不转发任何代理流量，只负责“决定给客户端哪些节点”。

你的 Mac（测速机）

tools/quality.mjs 每 2 小时
对「数据面 × 入口」逐个实测
TLS+WS 握手 → 204×3（延迟/抖动）
→ 下载 256KB（吞吐）→ 查出口国家
算分 S/A/B/C → 写 KV quality
为什么必须在这跑：
只有客户端能看到「你的网络 → CF 边缘」这段延迟。

数据面 · mux-core / core2 / core3（真正转发）

④ 客户端用 TLS 连到「优选 IP:443」，SNI/Host = mux-core.pages.dev
CF 边缘按 Host 把请求路由到对应 Pages 项目的 Worker
⑤ Worker 解析 WebSocket 里的 VLESS 头，拿到目标 www.google.com:443
用 connect() 建立 TCP，双向 pipe 转发
⑥ 目标响应原路返回：Worker → CF 边缘 → 你的客户端

四段链路（哪段决定快慢）

A. 你 → CF 边缘 IP：由优选入口决定（测速表里的延迟）
B. 边缘 → Worker：CF 内部，通常 <5ms
C. Worker → 目标：由落地机房决定（测速表里的国家/吞吐）
D. 目标 → 你：原路返回
所以「优选 IP」只优化 A 段；「出口国家」决定 C 段的远近。
